# WebSocket 서버 소스 분석

## 1. 프로젝트 개요

Node.js와 `ws` 라이브러리로 구현한 WebSocket 에코 서버이다. 클라이언트가 메시지를 보내면 서버는 내용을 콘솔에 출력하고, `서버 에코: ` 접두사를 붙여 해당 클라이언트에 응답한다.

- 접속 주소: 로컬 실행 기준 `ws://localhost:8081`
- 통신 방식: WebSocket을 통한 양방향 메시지 송수신
- 모듈 방식: CommonJS (`require`)
- 데이터 저장: 없음
- 클라이언트 간 메시지 공유 및 브로드캐스트: 없음

## 2. 파일 구성

```text
server/
├── server.js          # 서버 생성 및 연결·메시지·종료 이벤트 처리
├── package.json       # 프로젝트 정보, 스크립트, 의존성 선언
├── package-lock.json  # 설치할 의존성 버전과 무결성 정보
├── README.md          # 소스 분석 및 실행 안내
└── node_modules/      # 설치된 의존성
```

### 패키지 설정

| 항목 | 현재 값 | 의미 |
| --- | --- | --- |
| 패키지 이름 / 버전 | `server` / `1.0.0` | 프로젝트 식별 정보 |
| `type` | `commonjs` | CommonJS 모듈 사용 |
| `dependencies.ws` | `^8.22.0` | WebSocket 서버 구현용 의존성 |
| 잠금 파일의 `ws` 버전 | `8.22.0` | 잠금 파일 기준 설치 버전 |
| `main` | `index.js` | 실제 구현 파일인 `server.js`와 불일치 |
| `scripts.test` | 오류 메시지 출력 후 종료 코드 1 반환 | 실제 테스트가 아닌 기본 자리표시자 |
| 라이선스 선언 | `ISC` | `package.json`에 기재된 값 |

`main`의 불일치는 `node server.js`로 직접 실행하는 데 영향을 주지 않는다. 다만 패키지 진입점으로 사용할 경우 정리가 필요하다. 명시적인 `start` 스크립트도 없으므로 아래의 직접 실행 명령을 사용한다.

## 3. 실행 방법

Node.js와 npm이 설치된 환경에서 프로젝트 디렉터리로 이동한 후 실행한다.

```powershell
npm ci
node server.js
```

`npm ci`는 `package-lock.json`을 기준으로 의존성을 설치하며, 기존 `node_modules`가 있으면 재설치한다. 의존성이 이미 설치되어 있다면 `node server.js`만 실행해도 된다.

실행 시 다음 메시지가 출력된다.

```text
웹소켓 서버가 8081 포트에서 실행 중입니다...
```

이 출력은 서버 생성 직후 실행되는 로그이며, `listening` 이벤트에서 출력하는 준비 완료 확인 메시지는 아니다. 포트가 이미 사용 중이면 서버 실행에 실패할 수 있다. 종료할 때는 실행 터미널에서 `Ctrl+C`를 누른다.

포트는 `server.js`에 `8081`로 고정되어 있다. 환경 변수나 별도 설정 파일을 읽는 코드는 없다. 또한 `host`를 지정하지 않으므로 로컬 전용 바인딩으로 제한된 구성은 아니다. 외부 접속 가능 여부는 실행 환경의 네트워크 및 방화벽 설정에 따라 달라진다.

## 4. 소스 코드 상세 분석

### 4.1 라이브러리 로딩 및 서버 생성

```javascript
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8081 });
```

`ws`를 불러와 8081 포트에서 연결을 받는 서버를 생성한다. 기존 HTTP 서버를 전달하지 않고 포트를 지정하는 형태이다. 애플리케이션 코드에는 웹 페이지 제공이나 REST API 처리가 없다.

### 4.2 연결 이벤트

```javascript
wss.on('connection', (ws) => {
  // 연결별 이벤트 등록
});
```

클라이언트 연결이 성립하면 `connection` 콜백이 실행된다. `wss`는 서버 전체를 나타내며, 콜백 인자인 `ws`는 방금 연결된 클라이언트와 통신하는 개별 소켓이다. 각 연결에 메시지 수신 및 종료 이벤트를 등록한다.

### 4.3 메시지 수신 및 응답

```javascript
ws.on('message', (message) => {
  console.log(`수신된 메시지: ${message}`);
  ws.send(`서버 에코: ${message}`);
});
```

수신한 메시지를 템플릿 문자열에 삽입하여 콘솔에 출력하고 응답을 만든다. 원본 데이터를 그대로 되돌려 보내는 방식이 아니라 문자열로 변환한 값에 접두사를 붙이는 방식이다.

- `안녕하세요` 수신 → `서버 에코: 안녕하세요` 응답
- 응답 대상은 메시지를 보낸 연결 하나이다.
- JSON 파싱, 명령 분기, 데이터 검증은 수행하지 않는다.
- 바이너리 여부를 구분하지 않으므로 바이너리 데이터를 원본 그대로 보존하는 에코 용도로는 적합하지 않다.

### 4.4 연결 종료

```javascript
ws.on('close', () => {
  console.log("클라이언트 연결 종료");
});
```

연결 종료 시 로그만 출력한다. 종료 코드나 사유는 기록하지 않으며, 별도의 세션 저장 및 정리 로직은 없다.

## 5. 처리 흐름

```text
node server.js 실행
  → ws 라이브러리 로딩
  → 8081 포트의 WebSocket 서버 생성
  → 클라이언트 연결 시 connection 이벤트 발생
      → 접속 로그 출력
      → 해당 연결의 message / close 이벤트 등록
      → 메시지를 받을 때마다
          → 수신 내용 로그 출력
          → 보낸 클라이언트에 "서버 에코: ..." 전송
      → 연결 종료 시 종료 로그 출력
```

여러 클라이언트가 연결되어도 각 소켓의 콜백이 자신의 연결에 응답한다. 사용자 식별이나 방 생성 기능은 구현되어 있지 않다.

## 6. 동작 확인 예제

서버를 실행한 상태에서 로컬 테스트 페이지의 브라우저 개발자 도구 콘솔에 다음 코드를 입력한다. 페이지 보안 정책에 따라 연결이 제한될 수 있으며, HTTPS 페이지에서는 비암호화 `ws://` 연결이 차단될 수 있다.

```javascript
const socket = new WebSocket('ws://localhost:8081');

socket.addEventListener('open', () => {
  socket.send('안녕하세요');
});

socket.addEventListener('message', (event) => {
  console.log('서버 응답:', event.data);
});

socket.addEventListener('error', (event) => {
  console.error('WebSocket 연결 오류:', event);
});

socket.addEventListener('close', () => {
  console.log('연결이 종료되었습니다.');
});
```

기대하는 브라우저 출력:

```text
서버 응답: 서버 에코: 안녕하세요
```

응답을 확인한 뒤 연결을 닫는다.

```javascript
socket.close();
```

서버 콘솔에는 접속, 수신 메시지, 연결 종료 로그가 순서대로 출력된다.

## 7. 현재 구현의 제약 및 개선 지점

| 구분 | 현재 구현 | 개선 방향 |
| --- | --- | --- |
| 실행 설정 | 포트 하드코딩, `main` 불일치 | 포트 설정 분리, 진입점 정리, `start` 스크립트 추가 |
| 오류 처리 | 서버 및 개별 소켓의 `error` 핸들러 없음 | 포트 바인딩 실패와 연결 오류 처리 |
| 접근 제어 | 인증 및 Origin 검사 코드 없음 | 연결 허용 정책과 인증 처리 추가 |
| 암호화 | 코드에 TLS 설정 없음 | 운영 환경에 맞게 WSS 또는 TLS 프록시 구성 |
| 메시지 처리 | 모든 입력을 문자열로 변환해 응답 | 메시지 형식 검증과 텍스트·바이너리 처리 구분 |
| 연결 상태 | 별도의 heartbeat 없음 | ping/pong을 통한 비정상 연결 감지 |
| 부하 관리 | 애플리케이션 차원의 크기·빈도·송신 버퍼 제어 없음 | 서비스 요구에 맞는 제한과 흐름 제어 추가 |
| 로그 | 메시지 본문을 콘솔에 출력 | 로그 수준과 본문 기록 정책 설정 |
| 종료 처리 | 프로세스 종료 시 연결을 정리하는 코드 없음 | 종료 신호 처리 및 연결 정리 추가 |
| 테스트 | 자동화 테스트 없음 | 접속, 응답, 다중 연결, 오류 및 종료 검증 추가 |

위 항목은 소스 분석에 따른 개선 제안이며 현재 구현된 기능은 아니다.

## 8. 분석 및 검증 범위

- 분석 대상: `server.js`, `package.json`, `package-lock.json`
- 문서 작성 환경: Node.js `v24.21.0`, npm `11.19.0`
- 수행한 검증: `node --check server.js` 구문 검사 통과
- WebSocket 실제 연결 및 송수신 테스트는 수행하지 않았으며, 위 예제의 출력은 소스 기준 기대 결과이다.
- `npm test`는 현재 자리표시자이므로 정상 동작 검증 수단으로 사용할 수 없다.
